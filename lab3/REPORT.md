## Задание 2. Таблица прогноза (код с классом Counter)

| № print | Прогноз (до запуска) | Фактический вывод | Причина расхождения |
|---|---|---|---|
| 1 | `A: 2 \| B: 15` | `A: 2 \| B: 15` | нет |
| 2 | `2 2` | `2 2` | нет |
| 3 | `2 100 2` | `2 100 2` | нет |
| 4 | `3 3 True` | `3 3 True` | нет |
| 5 | `10 3` | `10 3` | нет |

Пояснения:
* print 1: `a.inc()` → value A = 1; `b.inc(5)` → B = 15; `a.inc(a.value)` → a = 1+1 = 2?
  Нет: к моменту вызова `a.inc(a.value)` значение a равно 1, шаг = 1 → a = 2; b = 15.
* print 2: `Counter.total` — атрибут класса, равен 2 (создано два объекта).
  Обращение `a.total` не находит атрибут объекта и «проваливается» к атрибуту класса — тоже 2.
* print 3: строка `b.total = 100` **не меняет атрибут класса**: она создаёт новый
  *атрибут объекта* `total` у экземпляра `b` со значением 100. Поэтому `b.total` = 100,
  а `Counter.total` и `a.total` остаются равны 2. Это ключевое отличие атрибута класса
  от атрибута объекта: присваивание через объект никогда не изменяет общий атрибут класса.
* print 4: `c = a` — это не копия, а вторая ссылка на тот же объект; `c.inc()` увеличивает
  value общего объекта до 3; `a is c` → True.
* print 5: создаётся третий объект X(7), `inc(3)` возвращает 10; счётчик total становится 3.

## Задания 3-6. Класс Account (`lab3/models.py`)

* Конструктор принимает 4 поля: `login, quota_mb, used_mb, active`.
* Атрибут класса `count` увеличивается в конце `__init__` - **после всех проверок**,
  поэтому при ошибке объект не создаётся и счётчик не растёт.
* Проверки: login непустой; quota_mb 100-10000; used_mb 0-quota_mb (через сеттер свойства);
  active - bool. При нарушении - `ValueError` с именем поля и неверным значением.
* Метод-изменение `upload(mb)` - проверка mb > 0, наличия свободного места и активности записи.
* Расчётный метод `free_percent()` возвращает свободное место в % (round до 0,1), ничего не печатает.
* `__str__`: `Учётная запись ivanov: занято 500 из 2000 МБ, запись активна.` (логическое поле - словами).
* Инкапсуляция (задание 6): поле `used_mb` -> внутренний `_used_mb` + `@property`
  и `@used_mb.setter` с проверкой 0...quota_mb; из конструктора отдельная проверка убрана -
  `self.used_mb = used_mb` вызывает сеттер (перед этим в конструкторе задаётся `self.quota_mb`,
  чтобы сеттер знал границу).

| 7 | `{unit}` в f-строке | NameError: unit не определён как имя | `{Thermometer.unit}` |
| 8 | конструктор не проверял диапазон | проверка только в set_value | `__init__` вызывает `self.set_value(value)` |
